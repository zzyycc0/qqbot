# 陪伴与记忆插件配置核对要点

本文件把旧实例的配置审计整理成通用核对清单，不保存线上用户绑定、模型账户、位置、预算数值或运行统计。当前版本以 [dependencies.lock.md](dependencies.lock.md) 为准，脱敏配置结构见 [config-snapshot/](config-snapshot/)。

## 1. 身份和基础设置

- 确认机器人名称、人设来源和时区。
- 目标 QQ 用户列表由实例所有者重新设置；不要沿用历史用户绑定。
- 确认插件使用的 AstrBot 人格与陪伴面板内容没有重复冲突。
- 对管理面板配置认证，并限制为本机回环地址或受控 SSH 隧道访问。

## 2. 模型和费用

- 每个模型服务单独配置地址、密钥、模型名和计价信息。
- 所有插件请求经过本地模型网关，以便统一路由和记录用量。
- 为不同用途选择经过验证的模型；重新部署时不要假设历史模型账户仍可用。
- 在发送任何真实请求前确认余额、预算和供应商计费规则。

## 3. 主动消息

- 新实例默认保持关闭，先确认目标用户绑定和投递通道。
- 配置安静时段、每日上限、最短发送间隔和未回应后的降速规则。
- 主动消息发送前复核权限和额度，并保留可审计的候选与结果记录。
- 不要只根据旧实例的有效值判断新配置；检查面板展示的最终生效设置。

## 4. 生活状态与记忆

- 按需启用日程、状态、日记和事件能力。
- 只保存对后续对话有帮助且允许保存的信息；支持所有者查看、删除和备份。
- 群聊记忆与私聊记忆分开管理；默认不要开启不需要的群聊采集。
- 数据库和记忆保存在实例数据目录，不纳入公开源码仓库。

## 5. 验证清单

新环境完成配置后，先在面板检查插件加载、Provider 可用性、用户绑定、网关连接和备份状态。任何会产生费用或发送消息的验收都应由实例所有者明确决定并执行。
